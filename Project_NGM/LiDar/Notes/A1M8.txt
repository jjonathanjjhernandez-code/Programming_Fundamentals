[Protocol Basics]
The RPLIDAR uses a non-textual binary data packet based protocol to communicate with host systems. And all the packets transmitted on the interface channel share uniform
packet formats.
A communication session is ALWAYS INITIALIZED by a host system, via an MCU, PC or anything that can TALK with it!
The RPLIDAR itself will not send any data out automatically after powering up.
If a data packet is sent from host systems to Lidar, such a packet is called a Request.
Once an RPLIDAR receives a equest, it will reply the host system with a data packet called a Respone.

RPLIDAR will only start performing related operations required by a host system once after it receives a request.
If RPLIDAR should reply to the host system, it will send one or more required response packets.

In order to let the Lidar start scanning operation and send out data, a host system is required to send a pre-defined Start Scan request packet to RPLIDAR. RPLIDAR will start
scanning operation once after it recieves the request and the scan result data is sent out to the host system continously.
There are three different request/response modes based on the related request types:
//  *   *   *   *   *   Request/Response Mode    *   *   *   *   *//   
{In this mode of operation the host system should prevent sending extra request packets if the LIDAR is BUSY handling the current request and has not replied to host system yet.
These extra request packets WILL be discarded by the Lidar protocol stack and the Lidar will not have any chance to handle it.

}
//  *   *   *   *   *   Single Request-Multiple Response Modes    *   *   *   *   *//   
{In this mode the Lidar is asked to perform the scan operation. After a host system sends a Start Scan Request, the RPLIDAR will take distance scan measurement continously.
Once a scan measurement sample is retrieved, its related result data(distance,angle value) will be sent out as individual response packets.

Host systems are only required to send a single request packet with this mode but will recieve a continous response packet stream
with multiple response packets.
The host system can interrupt RPLIDAR and let it leave the multiple responses mode by sending a STOP request or any request packet.
After leaving the multiple repsonses mode, the RPLIDAR will continue to handle the request which has interrupted it.

The request packets sent by the host system during multiple responsers mode will be cached by the lIDAR protocol stack. After leaving the multiple responses mode, LIDAR will handle
the cached request.
}

//  *   *   *   *   *   Single Request-No Response    *   *   *   *   *//   
{For requests like STOP, RESET Core, RPLIDAR uses the single request- no response mode since there is no need to reply to the host system.
Host systems should wait for a period of time before sending another request since LIDAR needs time to process the request operation. Otherwise, the 
request may be discarded by the lIDAR protocol stack.
}

[Request Packet's Format]
All request packets sent by a host system share the following common format. Little endian byte order used.
Transmission Order
1.Start Flag{1 Byte}
2.Command{1 Byte}
Optional
3.Payload Size{1 Byte}
4.Payload Data{0-255 Bytes}
5.CheckSum{1 Byte}
(Must be submitted within 0-5 seconds)
A fixed 0xA5{literally one bye} is used for request packet, RPLIDAR uses this byte as the identification of a new request packet. An 8-bit command field MUST follow the start flag byte.

[Response Packet's Format]
All the response packets are divided into two classes: response descriptors and data responses.
If the current request received by RPLIDAR requires a response, RPLIDAR will always send a response descriptor packet FIRST and then send one or more data response packets based on the type
of requests sent by the host system.
Only one response descriptor packet will be sent out during a request/response session. 
The response descriptors carry the information of the incoming data responses. All the response descriptors share
a similar format.
1. Start Flag1 (1byte 0xA5)
2.  Start Flag2 (1byte 0x5A)
3.  Data Response Length(30 bits)
4.  Send Mode (2 bits)
5.  Data Type (1byte)
A response descriptor uses fixed two bytes' pattern 0xA5 0x5A for the host system to identify the start of a response descriptor.
The 30bit Data Response Length field records the size of a single incoming data response packet in byte
(All the incoming data response packets within a request/response session should have the same format and length). 
The 2bits Send Mode field describes the request/response mode of the current session.
Send Mode
    0x0: Single Request - Single Resposne Mode, Lidar will send only one data response packet in the current session
    0x1: Single Request - Multiple Response Mode, Lidar will continously send out data response packets with the same format in the current session.
The 1 Byte Data Type field describes the type of incoming data response packets. It is related to the type of the request RPLidar just received.
Host systems can choose different data receiving and handling policy based on this field.
Each type of response data has its own data format and packet length based on its type.

    *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   
        Major Working States and Transition Conditions
    *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   
RPLIDAR has the following 4 major states: Idle, Scanning, Request Processing and Protection Stop State.
[Idle]
The idle state is the default state of the Lidar which will be entered automatically after powering up or reset. Both the laser diode and the measurement system are
disabled in this state, and the whole system is in power saving mode.
[Scanning]
Once RPLIDAR enters the scanning state, the laser diode and the measurement system will be enabled and RPLIDAR will start measuring distance and sending the result out
continously.
[Request Processing State]
The Lidar enters into this state once it recieves request packets from the host system. During this process, the Lidar will NOT perform the scan operation and will NOT 
send any data out. It will only send out response data if it is required based on the request.
After the request has been processed, RPLIDAR will enter other status specified by the request.
[Protection Stop State]
Once the Lidar or if anything happens to it, it will stop the current operation and enter this state.
A host system can still communicate with the Lidar to query its working status. But the host system CANNOT
ask the RPLIDAR to perform scan operations unless the host system sends a Reset Request to reboot the RPLIDAR core system.
