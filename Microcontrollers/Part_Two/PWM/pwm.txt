Now that we know a bit about we can start trying out some cool stuff like PWM!
PWM is an abbreviation for Pulse Width Modulation. In this mode, the timer acts as an up/down counter.
This means that the counter counts up to its maximum value and then clears to zero. The advantage of the PWM
is that the duty cycle relation can be changed in a phase consistent way.

If the PWM is configured to TOGGLE the Output Compare Pin (OCx), the signal at this pin can look like what you see in
"Output Signal of PWM"
A low-pass filter at the output pin combined with the relative high speed of the PWM will cause a constant voltage level
instead of a square wave signal as the output signal.
VAVERAGE = (VHIGH*(x) + VLOW*(y))/(x+y)
where
x=OCRx*2
y=(MaxVal-OCRx)*2

[Example 4: Timer2 PWM Generation]
This examples shows how to generate voltages between VCC and GND at the output pin of the PWM (PB3/OC2A).
To observe this, PB3 should be connected to an LED. This PWM output signal has a duty relation of 1/8 to 7/8 (OCR2A = 0xE0)
The following initialization routine shows how to set up such a system...
**
void init_Ex4(void){
    //enable non inverting 8-bit pwm
    TCCR2A = (1<<COM2A1) | (1<<WGM21) | (1<<WGM20); //initiating Fast PWM mode with WGMxx bits then conducting Clear OC2A bit on compare match, set OC2A at BOTTOM(non inverting mode)
    //timer clock = i/o clock
    TCCR2B = (1<<CS20);//no prescaling at all!
    //set the compare value to control duty cycle
    OCR2A = 0xE0; //pretty sure this is 224? so.....87% duty cycle?
    //enable timer 2 output compare match interrupt
    TIMSK2 = (1<<OCIE2A);
    //set the OC2A pin as output
    DDRB |= (1<<OC2A_PIN) <---which is whatever one you chose! which i guess is PB3? which is also D11
}

Here are some of its summaries for each type.

[Fast PWM Mode]
Fast PWM works the same way as the normal counter. The Control Logic receives the signal and increments the TCNTx register. When a match
is detected the OCFnx flag is set and signal is sent to the Waveform Generator.
The Waveform Generator then changes the state of the CNx pin(the state is determined by te selected mode...and obviously each timer has its
own dedicated pins).
When the TCNTn register passes the TOP value (0xFF or OCRnA....basically either the overflow or your compare number you placed in the OCRnA register)
it simply overflows back to 0, at the same time the OCFnx flag is set.
The OCFnX flag can be configured to trigger an interrupt. The OCFnx flag can be cleared by software,, but as always is cleared automatically when an
interrupt request is triggered.

*-Due to the high frequency of this mode it is best left for DAC, fading LEDs, rectification and Power Regulation-*

[Phase Corrected PWM]
The phase corrected mode counts up until it hits the TOP value(FIXED, OCRnA or ICRn...which the ICRn might just be external captire of the pins?)
then starts to count down until it hits the BOTTOM(0).
The Control Logic receives the signal and increments the TCNTn register. When a match is detected the OCFnx flag is set and signal is sent to the Waveform
Generator.
The WGM then changes the state of the OCNx pin(clear,toggle,etc determined by by COMxAx bits in TCCRxA registers).
When the TCNTn register hits the TOP value the OCFnx flag is set.
The OCFnx flag can be configured to trigger an interrupt. The OCFnx flag can be cleared by software, but is automatically cleared when interrupt request is
triggered.

This mode can be inverted or non-inverted.
In the non-inverting mode, the OCn pin is LOW on the Compare Match between TCNTn and OCRnx, and HIGH on the Compare Match while counting down.
(and vice versa)

In either case, the PWM logical block is necessary to get you intermediate voltages that isn't just 3V3 or GND.
It short, PWM toggles the logical output ON and OFF very fast, so fast that whatever is attached to the output cannot fully react.
But take notice to this! If you make a PWM signal and you grab an osciliscope to measure the at the output pin what you'll read is most defenitiely the logical
high and low of the PWM logical block.....but those look like square waves....
In most cases we typically DO want an actual sinusoidal wave....albeit DC-to-AC inverter is a very good example.
BUT for that to happen you need a medium or some sort of load to filter out or "average" out those pulses!
You see take an LED for an example, you can drive well above 6Hz and hit the 100MHz BUT the LED itself does not really change, what changes is your eye seeing the
brightness or dimness of the LED and that changes WITH frequency.
Your eyes somehow in someway average out those pulses to have an AC output of the LED brightness.
Motors work in the exact same way, turn the current on for a some time the induced voltage begins to rise, turn it off at the right time and the induced voltage rises
BUT in the opposite direction looking like this {induced voltage with respect to TIME in seconds or something like that....}

But these reactions times as mentioned before is super dependent on the duty cycle of your PWM signal{not just frequency!}. Say  your frequency is 10kHz PWM for an LED with a duty cycle of
230/255~=90%
and one with
150/255~=59%
You can tell that the 90% duty cycle will be "brighter" than the 59% duty cycle because the LED is one 90% of the time!
